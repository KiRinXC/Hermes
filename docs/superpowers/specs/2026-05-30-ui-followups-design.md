# Hermes UI Follow-ups Design

## Goal

修正三处已验收出的 UI/交互问题：

1. 新增浮窗字号需要可配置，并真实作用于浮窗内容。
2. 图标大小选择器两端应显示 Hermes 自身的真实图标，而不是临时绘制的替代图形。
3. 点击右下角启动提醒后，设置窗口必须抬到最前，不能被其他窗口盖住。

## Scope

本次只调整现有设置页、翻译浮窗和提醒点击后的设置窗激活路径，不引入新的设置分组，不改动翻译逻辑，不重构托盘架构。

## Design

### 1. 浮窗字号控制

保留 `UiSettings.FontSize` 作为唯一字号来源，但把设置页外观区的交互从连续滑块调整为与图标大小一致的横向五档选择器。左侧显示小 `A`，右侧显示大 `A`，中间五个点对应实际字号档位。保存时仍写回 `UiSettings.FontSize`，浮窗通过 `TranslationPopupWindow.ApplyTheme()` 同时更新译文正文和原文预览字号。

### 2. 真实图标预览

设置页图标大小选择器左右两端的预览不再使用临时 Path 图形，改为直接复用 Hermes 现有图标资源，以保证预览和真实悬浮按钮视觉一致。预览只承担尺度提示，不影响实际悬浮按钮的渲染路径。

### 3. 提醒点击置顶

提醒点击仍复用 `SettingsRequested -> ShowSettingsWindow()` 主路径，但 `ShowSettingsWindow()` 需要在显示或重新激活设置窗时执行一次显式前台提升：必要时先恢复窗口状态，再临时置顶、`Activate()`、聚焦后恢复 `Topmost=false`。这样能跨越当前前台应用，把设置窗可靠带到最前。

## Testing

- 设置页回归测试覆盖：
  - 字号选择器是五点横向控件而不是滑块。
  - 图标大小预览使用真实应用图标资源。
- 浮窗回归测试覆盖：
  - `ApplyTheme()` 同时更新 `BodyText` 和 `SourcePreviewText` 的字号。
- 启动提醒/设置窗回归测试覆盖：
  - 通知点击最终走显式置顶激活路径，而不只是普通 `Activate()`。
